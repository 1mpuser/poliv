# История

### 2026-09-23 — первая версия
- Стек на Docker Compose: PostgreSQL 16, FastAPI, React SPA, Caddy с HTTPS.
- Растения, полив, подкормки с чередованием удобрений, лампа (своя и общая), пересадки, сводка,
  история с фильтрами, графики за 8 недель, настройки, добавление растений.
- Интерфейс по макету из `design/`, светлая и тёмная тема, русский язык.
- Домен, порт и режим TLS вынесены в `.env`; локальный домен `polivalochka.cool:1477` с сертификатом
  от локального CA Caddy.

### 2026-09-24 — прод на polivalochka.ru
- Домен зарегистрирован в reg.ru 23.09, делегирование в зоне .ru появилось в ночь на 24.09.
- Развёрнуто на VPS трекера за его Caddy (`docker-compose.server.yml`, `deploy/deploy-server.sh`);
  фронтенд переименован в `poliv-web` из-за конфликта имён в сети трекера.
- Сертификат Let's Encrypt через TLS-ALPN, ежедневный бэкап БД по cron.

### 2026-09-24 — мультиучётки
- Вход по почте, вкладка «Админка» (создание с генерацией пароля, новый пароль, блокировка, удаление),
  «Аккаунт» в настройках, CLI `set-owner` / `create-user` / `reset-password` / `make-admin`.

### 2026-09-24 — свет
- Город учётки (поиск Open-Meteo), световой день и солнечные часы с учётом облачности по дням.
- Расписание программируемой розетки для своей и общей лампы; фоновая задача создаёт по нему сессии.
- Норма всего света на растение (`light_target_hours`), плитка «Свет», подсказка «не хватает N ч — лампа с … до …»,
  график солнце + лампа по неделям. Кнопка «Лампа» гасит и лампу, горящую по расписанию.
- Бэкап БД перед каждой выкаткой. Идеи на будущее — `docs/ideas.md`.
- Найдено при выкатке: `docker compose exec` в скрипте, переданном через `ssh … bash -s`, читал stdin и
  проглатывал остаток скрипта — деплой «успешно» завершался без пересборки. Теперь `</dev/null`, сервер
  хранит `/opt/poliv/REVISION`, а `release.sh` падает, если там не HEAD.

### 2026-09-25 — лампы как объекты и умная розетка
- Лампы — отдельные объекты учётки; растение под лампой — период привязки (`plant_lamps`).
  Перенос растения и удаление лампы (архив) прошлые часы не меняют (миграция 0004).
- Режим «Авто»: досветка до нормы самого требовательного растения — половина утром до рассвета,
  остаток вечером после заката. Умная розетка через Умный дом Яндекса, команда только при смене состояния.
- Раздел «Лампы» в настройках, токен Яндекса в «Свет», имя лампы в истории, чипы ламп на дашборде.

### 2026-09-25 — дневная досветка в «Авто»
- Если утра и вечера на норму не хватает, остаток лампа добирает днём — вплотную перед закатом, слитно
  с вечерней досветкой (в пасмурный день лампа горит и днём). Схема БД не менялась.

### 2026-09-27 — проверка грунта и пауза лампы
- «Проверил» вместо полива по расписанию: счётчик сбрасывается и поливом, и проверкой грунта; в сводке
  отдельно дата последней проверки и дни с последнего полива (миграция 0005, `soil_checks`).
- «Пауза 10 мин» лампы: розетка гаснет сразу, через 10 минут лампа сама продолжает. Досветка не теряется —
  хвост `after_pause` сдвигает недогоревшее; `replan_auto` такие сессии не удаляет.
  `lamps.paused_until`, `lamp_sessions.after_pause`.

### 2026-09-27 — исправления паузы лампы
- Пауза и кнопка «выкл» теперь гасят **все** горящие сессии лампы (ручная и досветка могли идти одновременно),
  каждой — свой хвост; продление/«Продолжить» работают со всеми хвостами паузы.
- `tick` сбрасывает зависший `paused_until` даже без смены состояния розетки; пауза считается активной только
  при `paused_until > now` и наружу в прошлом отдаётся как `null`. `HTTPException` из сервиса убран — 409 отдают
  роутеры (`LampNotOn`/`LampNotPaused`).

### 2026-09-27 — описание сайта для Safe Browsing

- Safari/Google Safe Browsing пометили polivalochka.ru как «Deceptive» (страница с одной формой пароля на новом домене).
  В `index.html` — название «Поливалка — трекер полива растений», `meta description` и статический текст о сервисе
  внутри `#root` (виден роботам без JS, React его заменяет). На экране входа — заголовок «Поливалка» и строка о том,
  что это закрытый трекер растений.

### 2026-09-27 — бэкенд переписан на Go
- Python (FastAPI + SQLAlchemy + Alembic) заменён на один статический бинарник Go (`backend-go/`):
  `net/http`-роутинг, `pgx/v5`, `golang-jwt`, `golang.org/x/crypto` (scrypt, hkdf). API один в один —
  пути, коды, JSON-поля и форматы Pydantic (float `12.0`, ISO-даты `+03:00`, пустые списки `[]`).
- Совместимость с данными подтверждена: старые scrypt-хэши, JWT от PyJWT и Fernet-токен Яндекса
  читаются новым кодом (и обратно). На копии рабочей базы Go стартует без изменения схемы
  (`alembic_version` не трогается), все GET-эндпоинты (`/plants`, сводки, история, статистика,
  лампы, настройки, свет) дают тот же JSON, что Python.
- Схема БД на пустой базе поднимается базовой SQL-миграцией (эквивалент Alembic 0001–0005):
  частичные индексы `uq_plant_lamp_open`/`uq_lamp_one_open`, `ON DELETE SET NULL` у подкормок.
  Будущие миграции — простые SQL-файлы (раннер `pg_migrations`).
- Docker: multi-stage, итоговый образ distroless (nonroot), healthcheck — подкоманда `/poliv healthcheck`;
  сервис по-прежнему `backend` с алиасом `poliv-api`, порт 8000, те же env (принимает и префикс `+psycopg`).
- CLI в том же бинарнике: `set-owner` / `create-user` / `reset-password` / `make-admin`.
- Память (docker stats, простои): Python ~74 MiB → Go ~6 MiB (после прогона запросов ~9 MiB).

### 2026-09-27 — устанавливаемое приложение на телефон
- Веб-манифест `frontend/public/manifest.webmanifest` (standalone, «Поливалка», цвета из светлой темы),
  иконки PNG 192/512 + maskable, сгенерированные из `icon.svg`; в `index.html` — manifest-ссылка и
  iOS-meta (apple-mobile-web-app-capable/title/status-bar-style). nginx отдаёт манифест как
  `application/manifest+json` отдельным location (без SPA-fallback). Service worker и офлайн-кэш
  намеренно нет: `/api` кэшироваться не должен.
- Вёрстка на 320/360px (проверено headless Chrome, CDP, `scrollWidth <= clientWidth` на всех экранах
  с намеренно длинными названиями): действия в карточке — 2×2 ниже 380px; длинные слова не вылезают
  (`overflow-wrap: anywhere` у названий, меток, чипов, заголовка шторки); сетки с полями —
  `minmax(0, 1fr)` (внутренняя ширина input выталкивала форму удобрения за карточку); чипы ламп на
  дашборде ограничены `max-width: 100%`; строка удобрения/лампы с тремя кнопками переносит кнопки вниз;
  в standalone шапка и экран входа сдвинуты на `env(safe-area-inset-top)`.
- Свет: Go-порт писал длительности Open-Meteo в секундах вместо часов (в сводке «36 402,9 ч» солнца,
  «Авто» у лампы считал, что досветка не нужна). Перевод в часы — в `light.parseDays` (тест),
  миграция 0002 делит на 3600 уже сохранённые значения > 24.
- Подсказка света в режиме «Авто»: «даже с досветкой» — только когда досветка в плане есть; пустой план —
  «досветка ещё не запланирована» или «лампа на паузе до …».

### 2026-10-03 — корневая подкормка автоматически создаёт полив
- Корневая подкормка (`method=root`) в той же транзакции записывает полив раствором: заметка «с подкормкой»,
  то же время, что подкормка. Листовая (`foliar`) полив не создаёт.
- Дубль не плодится: если в этот календарный день (в зоне учётки) полив уже был, автополив не создаётся.
- Автополив привязан к подкормке (`feeding_logs.watering_id`, `ON DELETE SET NULL`, миграция 0003):
  удаление или отмена корневой подкормки убирает и автополив, вручную созданный полив не трогает.
  В `updateFeeding` автополив едет вместе с подкормкой: root→foliar удаляет его, foliar→root создаёт,
  смена времени двигает `watered_at`.
- Недельная статистика и история считают автополив как обычный полив — это полноценная запись `watering_logs`.

### 2026-10-11 — токен Яндекса после 401/403 перепроверяется раз в 15 минут
- Одиночная ошибка Яндекса перестала блокировать розетку до ручного вмешательства: пока токен помечен
  недействительным (`user_settings.yandex_token_invalid`), команда в фоне не идёт на каждый минутный тик,
  а не чаще раза в 15 минут от момента 401/403 (новое поле `yandex_token_invalid_at`, миграция 0004).
- После паузы токен перепроверяется; удалось — флаг снимается, `yandex_status` возвращается в `"ok"`,
  лампа включается/выключается сама без повторного сохранения токена. Успешный список устройств тоже
  снимает пометку. У уже помеченных до деплоя записей `invalid_at` пуст — первая проверка происходит
  на первом же тике.

### 2026-10-11 — лампа честно пишет «розетка не отвечает», а не «горит»
- Если у лампы есть розетка и записан `last_error`, интерфейс больше не показывает «горит» по плану:
  чип лампы на дашборде пишет «<Лампа> должна гореть/быть выключена — розетка не отвечает» с причиной,
  кнопка «Лампа» в карточке растения — «Розетка не отвечает». Ошибку теперь видно на главной, а не только
  в списке ламп.
- Единое правило вынесено в `frontend/src/lamp.ts` (`plugIssue`): розетка есть (`has_device`/`device_id`)
  и `last_error` не пуст; главная, карточка растения и список ламп проверяют одинаково.

### 2026-10-11 — ручное включение в «Авто» не горит всю ночь
- Кнопка «Лампа» в режиме «Авто» при включении сразу закрывает ручную сессию на сегодняшнее
  `evening_not_after`, а после него — на час (`autoManualGrace`): вечером лампа не висит открытой до
  ручного выключения и не обрезает досветку будущей открытой сессией. В «Вручную» и «По расписанию»
  поведение прежнее — открытая сессия.
- Пауза ручной сессии с концом оставляет тот же конец в хвосте (не открывает его); «Отменить» не трогали.

### 2026-10-17 — у каждого растения свой набор удобрений и интервал подкормки
- Набор удобрений — у растения, а не общий для учётки: таблица `plant_fertilizers` (миграция 0005)
  и поле `plants.fertilizing_interval_days` (свой интервал, `null` — как у удобрения). `PickNextFertilizer`
  чередует только набор растения.
- Применено только для существующих растений: бэкфилл привязал им все удобрения учётки; новые растения
  по умолчанию без удобрений (подкормка `off`, пока набор не выбран).
- API: растение (создание/PATCH/чтение) получает `fertilizer_ids` и `fertilizing_interval_days`;
  чужое/несуществующее удобрение — 404, подкормка удобрением не из набора — 422; сводка отдаёт
  `fertilizers` (набор) и `feed.next` — форма и подкормка работают только с набором растения.
- Фронтенд: в форме растения галочки удобрений учётки и поле «Подкармливать раз в N дней»;
  форма подкормки и сводка берут удобрения из набора растения.

### 2026-10-17 — растение без удобрений не роняет страницу
- Бэкенд: `fertilizer_ids` у растения без привязок отдавался `null` вместо `[]` — нил-слайс
  (`FertilizerIDsForPlant` и отсутствие ключа в `FertilizerIDsByUser`). Теперь пусто всегда массив:
  в списке, чтении, создании, PATCH и в `plant.fertilizer_ids` сводки; `fertilizers` сводки тоже `[]`.
- Фронтенд: `PlantForm` (галочки набора) и `PlantActions` (форма подкормки) защищены от `null`/`undefined`
  через `?? []`, чтобы старый ответ не валил страницу растения.
- API-тест `TestPlantNoFertilizersEmptyArrays` проверяет по сырому телу ответа `"fertilizer_ids":[]`
  и `"fertilizers":[]`.
