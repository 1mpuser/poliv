# Лампы как объект и умная розетка через Яндекс Умный дом

Дата: 2026-09-25. Статус: дизайн согласован, ждёт ревью спецификации.

## Зачем

Лампа сейчас неявная: «своя лампа растения» (`plant_id`) или «общая лампа учётки» (`plant_id IS NULL`,
светит всем растениям). Приложение розеткой не управляет — только считает часы по расписанию
программируемой розетки.

Нужно:
- лампа — отдельный объект, ламп у учётки несколько (например, «Лампа цитрусы» для лимона и лайма,
  другая — для других растений); растения привязываются к лампе на портале;
- лампа с умной розеткой (Tuya/Smart Life, привязана к Алисе) включается Поливалкой сама — на столько,
  сколько нужно её растениям до нормы света.

Критерий успеха: лимон (норма 12 ч) и лайм (10 ч) под «Лампой цитрусы» в пасмурный день с 3 ч солнца —
розетка сама включается утром и вечером, и оба растения набирают норму (лимон — ровно, лайм — с запасом),
без ручных действий и без расписания в самой розетке.

## Решения (из обсуждения)

| Вопрос | Решение |
|---|---|
| Растений под лампой с разной нехваткой | Лампа горит по **максимуму** нехватки |
| Когда досвечивать | **Поровну утром и вечером**: утро заканчивается на рассвете, вечер начинается на закате |
| Через что управлять | **API Умного дома Яндекса** (`iot:view`, `iot:control`), OAuth-токен учётки |
| Режимы лампы | `auto` (до нормы), `schedule` (интервалы, как сейчас), `manual` (только кнопка) |
| Растение ↔ лампа | У растения **одна** лампа или ни одной (многие-ко-многим — не делаем) |

Отвергнуто: Tuya Cloud напрямую (пробный пакет надо продлевать), вход по QR через
`tuya-device-sharing-sdk` (чужой client id Home Assistant), локальный tinytuya (сервер не в квартире).

## Модель данных

Новая таблица `lamps`:

| Поле | Тип | Смысл |
|---|---|---|
| `id` | pk | |
| `user_id` | fk users, cascade | владелец |
| `name` | str(100) | «Лампа цитрусы» |
| `mode` | enum `lamp_mode`: auto / schedule / manual | |
| `device_id` | str, null | id устройства в Яндексе; null — розетки нет, только учёт |
| `device_name` | str, null | имя устройства для показа |
| `morning_not_before` | time, default 06:00 | утренняя досветка не раньше |
| `evening_not_after` | time, default 23:00 | вечерняя досветка не позже |
| `last_state` | bool, null | что последним отправили в розетку |
| `last_error` | text, null | последняя ошибка розетки |
| `last_error_at` | timestamptz, null | |

Изменения:
- `plants.lamp_id` → fk lamps, `ON DELETE SET NULL`, null;
- `lamp_sessions`: `plant_id` заменяется на `lamp_id` (fk lamps, cascade, NOT NULL);
  новое поле `source` enum `lamp_source`: manual / schedule / auto;
  `uq_lamp_one_open` пересоздаётся на `lamp_id` (одна открытая ручная сессия на лампу);
- `lamp_schedules`: `plant_id` заменяется на `lamp_id` (fk lamps, cascade, NOT NULL);
- `user_settings.yandex_token` — text, null, зашифрован Fernet (`cryptography`), ключ выводится из
  `JWT_SECRET` через HKDF (новых переменных окружения нет; смена `JWT_SECRET` сбрасывает токен —
  его придётся ввести заново).

Часы растения = все сессии его лампы (`lamp_hours_between` без изменений, меняется только выборка).
Особый случай «общая лампа светит всем» исчезает.

### Миграция 0004

Для каждой учётки:
1. Если есть сессии или расписание с `plant_id IS NULL` — лампа «Общая лампа».
2. Для каждого растения с собственными сессиями/расписанием — лампа «Лампа <имя растения>»,
   растение привязывается к ней.
3. Остальные растения учётки — к «Общей лампе» (если она создана).
4. `mode` = `schedule`, если у лампы есть расписание, иначе `manual`.
5. `source` старых сессий: `schedule`, если есть `schedule_id`, иначе `manual`.

Потеря данных: у растения, которое имело и свою лампу, и общую, часы общей лампы из истории выпадут.
Перед выкатом — проверочный запрос только на чтение на проде; если такие растения есть, сказать
пользователю до миграции.

`downgrade` — обратное преобразование без гарантии для растений, привязанных к одной лампе с другими.

## Расчёт досветки (чистые функции, `services/summary.py`)

Для лампы в `auto` на день D (время — `settings.zone`):

- `plant_deficit = target − sunshine(D) − lamp_hours(D, без auto-сессий)`;
- `lamp_need = max(0, max(plant_deficit по растениям лампы))`; растений нет → 0.

Утро (`plan_morning`): длительность `lamp_need / 2`, конец = рассвет, начало =
`max(рассвет − lamp_need/2, morning_not_before)`. Если рассвет ≤ `morning_not_before` — утра нет.

Вечер (`plan_evening`): считается на закате заново по фактическим данным:
`остаток = max(0, max(target − sunshine(D) − все часы лампы за D))`,
начало = закат, конец = `min(закат + остаток, evening_not_after)`. Если упёрлись — растение
показывает недобор обычным статусом.

Хранение: auto-сессии — обычные `lamp_sessions` с `source=auto`, по одной на часть дня.
Пока часть не началась, её пересоздают на каждом шаге (смена нормы, новое растение, уточнённый
прогноз применяются сразу). Начавшиеся и прошедшие не трогаются.

`auto` без города (нет `daylight_days`) — 400 «Задайте город в настройках».

## Управление розеткой

`services/yandex.py`:
- `list_devices(token) -> list[Device]` — `GET https://api.iot.yandex.net/v1.0/user/info`,
  только устройства с умением `devices.capabilities.on_off` (id, имя, комната);
- `set_on(token, device_id, on: bool)` — `POST /v1.0/devices/actions`;
- ошибки: `YandexAuthError` (401/403), `YandexError` (прочее, сеть; таймаут 10 с).

Фоновая задача в `main.py` (lifespan), **раз в минуту**, отдельно от получасового `sync_all`:
1. для ламп `auto` — пересчитать будущие auto-сессии на сегодня;
2. для каждой лампы с `device_id`: `want = есть сессия, покрывающая now`;
   если `want != last_state` → `set_on`; успех → `last_state = want`, `last_error = null`;
   ошибка → `last_error`, `last_error_at`, `last_state` не меняется (повтор через минуту).

Команда уходит **только при смене нужного состояния** — выключение через Алису вручную Поливалка
не перебивает до следующего перехода по плану.

Кнопка «Лампа» (toggle) и «Отменить» после изменения сессии сразу вызывают тот же шаг для этой
лампы — без ожидания минуты. Ошибка розетки не отменяет сессию, а показывается в тосте.

Ошибки учётки: 401 от Яндекса → в настройках статус «токен недействителен».

## API

- `GET/POST /api/lamps`, `GET/PATCH/DELETE /api/lamps/{id}` — через `crud.owned_lamp_obj`
  (чужая — 404). Тело: `name, mode, device_id, device_name, morning_not_before, evening_not_after,
  plant_ids` (полная замена списка растений; чужое растение — 404).
- `PUT /api/lamps/{id}/schedule` — интервалы (замена нынешнего `PUT /lamp-schedules`).
- `POST /api/lamps/{id}/toggle` — ручное вкл/выкл (замена toggle по растению; toggle по растению
  остаётся как прокси на его лампу, растение без лампы — 400).
- `GET /api/yandex/devices` — список розеток по токену учётки.
- `PUT /api/settings/yandex-token` `{token | null}` — сохранить (сразу проверяется `list_devices`)
  или удалить. В `GET /api/settings` — только `yandex_status: none | ok | invalid`, сам токен не отдаётся.
- `PlantSummary.light`: `lamp: {id, name, mode, is_on, planned: [{start, end}], last_error}`;
  `schedule`/`shared_schedule` уходят.

## Интерфейс

- «Настройки → Свет»: город; «Токен Яндекса» (ввод, «Проверить», статус; ссылка на инструкцию).
- «Настройки → Лампы»: список (имя, режим, розетка, растения, горит ли, ошибка);
  sheet «Лампа»: имя, розетка (выпадающий список из Яндекса или «без розетки»), режим,
  для `schedule` — `LampScheduleEditor`, для `auto` — «не раньше / не позже», чекбоксы растений
  («сейчас: Лампа X» у привязанных к другой).
- «Настройки → Растение»: вместо «Своя лампа» — выбор лампы.
- Кнопка «Лампа»: переключает лампу растения; без лампы — неактивна с подсказкой.
- `LightHint` для `auto`: «Лампа цитрусы включится сама: 06:00–08:15 и 17:40–19:55».
- Только классы и токены макета, тексты — русский, числа и даты — `format.ts`.
